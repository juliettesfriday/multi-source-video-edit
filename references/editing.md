# 精剪与时间轴

1. 用 inspect_media.py 检查显示方向、有效像素、帧率、音轨、色彩/HDR。顺序先用用户明确顺序，再看内容衔接；文件名时间只是线索。
2. 获得实际录音转写与时间戳。参考稿用于核对专有名词和结构，不添加未说出的内容。保留原始识别与校对版。
3. 听看候选删减点，保留完整、自然的一次试录，检查跨素材接句；保留正常呼吸。不能仅以声量低判定无言。
4. 写 edit.json，源片秒数使用左闭右开区间，相对路径以 JSON 所在目录为基准：

```json
{"segments":[
  {"source":"clips/a.mp4","start":0.4,"end":8.2},
  {"source":"clips/b.mp4","start":1.0,"end":7.4}
]}
```

assemble.py 只执行已决定的保留表。边界尽量对齐源帧，确认不截断音节。删除清单字段建议：source,start,end,text,reason,kept_alternative,confidence。无言段写“无口播”，不清楚的文字标注不确定，不能按稿子编造。

检查开场、接缝、较长删段前后、片尾。恢复片段后重算后续字幕和章节。

## 时间映射

源区间 [a,b) 在成片从 T 开始，源时间 t 映射为 T+t-a。同一源文件可多次出现，不能用一个全局 offset 代替 EDL。

captions.py map 将源 SRT 按 EDL 映射，同时报告切口截中的字幕。它不能判断跨切口字幕中哪几个字被剪掉，报告必须复核，必要时用逐词时间戳拆句。

用户发来调速或另行删改的成片时，重新对齐。可用音频、可见字幕或时间码定位；只有确认同一字幕样式时才适合用已校对文字模板作逐帧匹配。不要假设整体恒定倍率。

## 句首裁切

以当前指定成片为输入，核对句首第一个音节和前一句结束。“52秒左右”不要求等于52.000。

trim.py 使用 MP4 流复制与 edit list 设置精确起播点；非关键帧裁切需要在文件内保留不可见的解码参考帧。它不是物理擦除，不能用来保证敏感内容已从文件数据删除。

裁切后检查实际首帧、包数据、音画、章节、完整解码，并在目标播放器/上传平台验证。平台不支持 edit list 时，说明需要重编码，选择合适方案；不能移到前一个关键帧多播一句，也不能未经验证声称边界重编码拼接无损。

明确“其他不变”时，保留烧录字幕、进度图形和旧计时文字；播放器章节元数据随时间轴平移。烧录进度条若需归零，必须重新合成，属于可见修改。
